## 一、核心流程路径对比（最快路径 vs 现路径）

### 流程 1：首次生成下载（主场景：上架前补齐图标）

| 步骤 | 理论最快路径 | 现路径（实际实现） | 差距 |
|---|---|---|---|
| 进入 | 直访 /tool/ | 同（PAGE001 一击或直访） | 无 |
| 上传 | 拖放 1 张图 | 点「选择图像」或拖放（`main.js:66-67,127-138`） | 无 |
| 配置 | 全默认（iOS+Android 已勾选、三选项已开，`tool/index.html:66-87`） | 同，零操作可跳过 | 无 |
| 生成 | 1 击 | 1 击（`main.js:244-287`） | 无 |
| 下载 | 1 击 | 1 击，但**点击后全量重算一遍**再组包（`main.js:359-365`） | 等待成本（P4 FN-09 已列 B） |

**结论**：交互步数=理论最短（3 次有效交互）；成本差距在信息与等待（FN-02 无预览、FN-09 重算）——均已列 P4 B 类，V1 原型已落地（`V1_ACCEPTANCE.md` §7）。

### 流程 2：临时替换图标（场景：改版后重新生成，PRD §3 场景 2）

- 现路径：预览态「更换图像」→ 选新图 → **旧结果区仍显示**（`main.js:191-239` processFile 不清空 resultSection、不影响下载按钮）→ 需用户自觉再点「生成」；若直接点「下载所有图标」，将用**新图**按当前平台组包——与所见旧结果不一致（UF-01，新发现）。
- 对照：改平台/选项同样不失效结果（P4 FL-04 已列）；换图维度是 FL-04 的缺口，建议合并扩展。

### 流程 3：从主页到达工具并返回

- 去程：PAGE001 →（在线工具）→ /tool/，1 击，达标（`web/public/index.html:302-315`）。
- 返程：无站内回链，仅浏览器后退（grep `tool/index.html` 无站内回链；P4 PG-03 已列 B，V1 已加品牌回链）。五要素中「返回」在页面级依赖浏览器，流程级依赖「重置」。

### 流程 4：落地页转化（下载桌面版 / 跳网页版）

- 网页版卡 → /tool/ 新窗口：达标。
- 桌面卡 → Gitee tag/3.0.0：版本固化 + 单一来源（IA-03，C）；点击后成败完全交给外部站点，无回执。
- 联系表单/移动菜单：旧版失效（P4 FN-03/FN-04 已列 B，V1 已修复规格）。

### 流程 5：desktop 本地导出（对照流程）

- 路径：打开图片（菜单/拖放）→（配置回填自 electron-store，`renderer.js:55-83`）→ 生成（有按钮禁用防重入，`renderer.js:415`）→ 选输出目录（dialog）→ 导出落盘 → 打开输出文件夹。
- 缺口：导出 `fs.writeFileSync` 直接覆盖同名文件，无任何确认（`iconGenerator.js:224`）——UF-04（新）；desktop 生成与 web 不同点：Contents.json 选项不生效（P4 FN-08 已列，随 C-4）。

## 三、异常流程三类评审（用户失败 / 系统失败 / 环境失败）

### 1. 用户失败（操作错误）
已覆盖 7 类（非图片 `main.js:193-196`、超 5MB `199-202`、解码失败 `235-238`、无平台点生成 `245-247`、无文件点下载 `351-353`、生成抛错 `283-286`、ZIP 失败 `398-402`），文案具体、停留可重试——达标。
缺口：**小图/非 PNG 静默通过**——hint「建议上传1024×1024像素的PNG图像」仅为建议（`tool/index.html:37`），上传 64×64 图会被拉伸放大到 1024 输出，无任何提示（P1 逆向报告流程 3 已记录行为；UF-08 立项）。拖放多文件取首个无提示（P4 FL-05 已定 D 照旧，维持）。

### 2. 系统失败（程序错误）
- 生成/组包异常：error 通知含 `{msg}`——有通知、无下一步指引（不告诉用户能做什么：重试？换图？换浏览器？）。建议方向：错误通知附「重试」动作或指引文案（轻量，属文案增强）。
- 常驻 loading 通知在异常路径已清理（`main.js:400` hideNotification）——无永久 loading，达标。
- 生成中重入：**web 无防护**——生成按钮全程可再点，两轮全平台 Canvas 生成并发执行（`main.js:244-287` 无禁用；对照 desktop `renderer.js:415` 有禁用）——UF-02（新）。P7 `STATE_MACHINE.md` §4 已定「V1 generating 标志拦截」，本评审要求将其升为正式 B 类条目。

### 3. 环境失败（运行环境）
- JSZip CDN 不可达：延迟到点击下载才报错（P4 FL-02 已列 B；PM-05 补充安全维度）。
- 旧浏览器/无 File API/Canvas：无检测无提示（page-spec §0.7 仅为约定文字）——UF-05（D）。
- GitHub Pages 站点自身不可达：静态站特性，无应用层兜底必要——不立项。

## 四、问题清单（UF-01 起；格式：当前设计/问题/影响/建议方向）

### UF-01 更换图像后结果与下载不失效【新发现 · B，建议并入 P4 FL-04 扩展】
- **当前设计**：processFile 成功后仅更新预览与按钮，不隐藏 resultSection、不标记结果过期（`web/public/js/main.js:191-239`）。
- **问题**：换图后旧结果仍在，直接下载会用新图按当前平台组包，所见非所得。
- **影响**：用户拿到与屏幕显示不符的图标包（换 logo 场景高发：新旧图标混发风险认知）。
- **建议方向**：P7 已定义 configKey 过期机制（`STATE_MACHINE.md` §3），将「源图变更」纳入 configKey 维度；结果区黄条提示同 FL-04 落地。

### UF-02 web 生成过程无防重入【新发现 · B；P4 未列、P7 已有方案】
- **当前设计**：handleGenerate 执行期间生成按钮不禁用（`web/public/js/main.js:244-287`），可再次点击并发执行；desktop 版生成期间禁用按钮（`desktop/src/renderer/renderer.js:415-416`）。
- **问题**：连点导致两轮全平台 Canvas 生成并发，通知互相覆盖（单通知条），行为不可预期；且与 desktop 行为不一致。
- **影响**：大图全平台场景卡顿加剧；通知语义混乱。
- **建议方向**：按 P7 state-management §4 落地 generating 标志；补「生成中重复点击」验收用例。

### UF-03 下载落盘无确认与兜底【新发现 · C】
- **当前设计**：下载触发后仅 success「下载已开始」（`main.js:397`），此后浏览器接管。
- **问题**：浏览器拦截弹窗下载/磁盘失败时，用户在应用层无任何感知与重试指引。
- **影响**：低概率但无兜底；用户可能重复点击造成重复下载。
- **建议方向**：文案补「请查看浏览器下载列表」；是否做更明确的确认机制属产品决策（C）。

### UF-04 desktop 导出直接覆盖同名文件【新发现 · C，随 P4 C-4 生效】
- **当前设计**：exportIcons 对目标路径 `fs.writeFileSync` 直接覆盖（`desktop/src/main/iconGenerator.js:224`），无存在性检查。
- **问题**：向已有输出的目录再次导出（常见：反复调整选项导出到同一目录）会静默覆盖旧文件。
- **影响**：用户历史产物无预警丢失。
- **建议方向**：覆盖前检测冲突并确认；若 C-4 决策放弃桌面壳则不落地。

### UF-05 旧浏览器/无 File API 环境无检测提示【新发现 · D】
- **当前设计**：page-spec §0.7 写「现代桌面/移动浏览器」，代码无特性检测（grep 无相关逻辑）。
- **问题/影响**：不兼容环境表现为按钮无响应，无解释。
- **建议方向**：观察不动（受众为开发者，环境过旧概率低；如做可加一次性 noscript/特性提示）。

### UF-08 小图/非 PNG 上传无信息提示【新发现 · B】
- **当前设计**：校验仅类型（image/*）与 5MB（`main.js:193-202`）；hint 建议文字不构成校验；小图按 Canvas 拉伸直接放大输出（`imageProcessor.js` drawImage，P1 逆向报告流程 3）。
- **问题**：用户上传 256×256 图生成 1024×1024 输出，质量劣化无任何提示，与 hint 的「建议」形成静默落差。
- **影响**：输出质量不可知的次品图标进入工程。
- **建议方向**：复用 F007 warning 通道（非正方形警告同构，非新功能）：源图短边 < 所选平台最大尺寸时出 warning「图像小于目标尺寸，放大输出可能模糊」，不阻断。
